What is Compute Efficiency?

The Question: Does the accuracy gain justify the extra cost?

We measure compute as parameter-passes — simply the number of model parameters multiplied by how many times the model runs. The guided pipeline costs 10.5B passes vs 7.5B for baseline — 40% more than baseline, but 30% less than just running the 3B model for all 5 votes (15B).

Simple Analogy

Imagine hiring a consultant (the guide) to write a brief strategy note before your team (5 workers) tackles a problem. The consultant costs extra time, but the team now works more efficiently with better direction. The question is: does the consultant's fee pay off in better results?

② Vote Consistency

02

What is Vote Consistency?

The Question: When the solver votes, how often do the votes agree — and are those agreements correct?

We run the solver 5 times per question. Vote consistency measures the fraction of those 5 votes that matched the correct answer. High consistency means the solver reliably reaches the right answer, not just getting lucky on a 3-2 split. A lift of 1.5× means guided consistency is 50% better than baseline.

Simple Analogy

Imagine asking 5 friends to solve the same puzzle independently. Without any guidance, maybe 2 get it right and 3 get it wrong (40% consistency). With a helpful hint, 4 out of 5 get it right (80% consistency). The majority vote then correctly picks the right answer — and more confidently.

③ Confidence Calibration

03

What is Confidence Calibration?

The Question: When the model is confident, is it actually correct? We use ECE (Expected Calibration Error) — lower ECE means confidence matches accuracy.

We treat vote agreement as confidence: if 5/5 votes agree, confidence = 100%. If 3/5 agree, confidence = 60%. A well-calibrated model at 100% confidence should be right ~100% of the time. ECE measures the gap between confidence and actual accuracy, weighted by how many questions fall in each bucket.

Real Example — PIQA Baseline Problem

On PIQA, the baseline solver votes A on 93.4% of questions — so 491 out of 500 questions have "100% confidence" (5/5 votes agree). But those unanimous answers are only correct 54.8% of the time — barely above random chance (50%). That is catastrophically miscalibrated: maximum confidence, minimum accuracy. ECE = 0.354. After guidance: ECE = 0.110, a 69% improvement.

Expected Calibration Error (ECE)
$$\text{ECE} = \sum_{b=1}^{B} \frac{|S_b|}{N} \cdot \left| \text{acc}(S_b) - \text{conf}(S_b) \right|$$

Where S_b = questions in confidence bucket b, acc = actual accuracy, conf = vote agreement. Lower ECE = better calibrated.

Statistical Proof

McNemar's Test — How We Prove It

Because every question is tested under BOTH conditions, we can ask: on the questions where the two conditions disagree, does guided win significantly more often than baseline?

?

Why McNemar's Test?

Standard tests assume independent samples. Here, each question is tested twice (guided and baseline) — they're paired. McNemar's test uses only the questions where the two conditions disagree. Questions where both got it right or both got it wrong don't count.

The 2×2 Contingency Table

Only B and C matter for the test. A and D cancel out — they tell us nothing about which method is better.

McNemar Chi-Square Statistic (with Yates correction)
$$\chi^2 = \frac{(|B - C| - 1)^2}{B + C}$$

Under H₀ (no difference), this follows a chi-square distribution with 1 degree of freedom. Large χ² → small p-value → reject H₀.

Sample Size Planning

Power Analysis — How Many Questions Do We Need?

Power analysis tells us the minimum N required to have 80% chance of detecting a real effect, given the expected effect size. Too few questions → we might miss a real effect (Type II error).

N?

Simple Explanation

Imagine trying to determine if a coin is biased. If you flip it 5 times, you can't tell much. If you flip it 1000 times, you can be very sure. Power analysis calculates: given the effect size we expect, how many flips (questions) do we need before we can trust the result? The formula depends on the discordant rate (how often the two conditions disagree) and the signal strength (B-C difference).

Power Analysis Formula for McNemar's Test
$$N_{\min} = \left( \frac{z_{\alpha/2}\sqrt{\pi_d} + z_\beta\sqrt{\pi_d - \delta^2}}{\delta} \right)^2$$
π_d = π_B + π_C   (discordant rate = fraction of questions where conditions disagree)
δ = π_B - π_C    (signal = how much more often guided wins than baseline)
z_{α/2} = 1.96    (for α = 0.05, two-sided)
z_β = 0.842      (for 80% power)

Boundary Condition

The RACE-High Null — When Guidance Doesn't Help

The N=500 clean null on RACE-High is not a failure — it tells us where and why the method works.

Reasoning vs. Retrieval
Verbal planning helps tasks that require generating a solution path. It does not help tasks that require locating pre-existing evidence in a passage. RACE-High answers are already in the text — the model just needs to find them. A plan can't help you search.
Simple Analogy

Reasoning task (PIQA, SVAMP): "How do you remove a stripped screw?" — You need to think through the physics and generate a solution. A verbal plan helps enormously.

Retrieval task (RACE-High): "According to paragraph 3, what year did X happen?" — The answer is already in the passage. Writing a plan first doesn't help you find the relevant sentence any faster.

The Two-Variable Interpretation

Variable 1 — Domain proximity: intuitively, a guide fine-tuned on ASDiv should be best at ASDiv. It is not. GSM8K FT beats ASDiv FT on the ASDiv test set by +4.0 pts. Domain proximity is a weak predictor of guide quality.

Variable 2 — Verbal reasoning richness: GSM8K problems embed arithmetic in multi-sentence contextual narratives and require multi-step verbal decomposition. The guide learns to produce structured, transferable reasoning scaffolds. ASDiv problems are sparse (one sentence, one operation) — the guide learns terse templates that don't generalise.

Conclusion: the relevant dimension for selecting fine-tuning data is verbal plan richness and structural diversity, not task-type overlap. This sharpens the paper's existing claim that "fine-tuning quality is the sufficient condition" — quality here means the training distribution's ability to teach generalisable verbal reasoning patterns.

T-1 · Accuracy Decomposition — Where Does the Gain Come From?

Simply saying "accuracy improved" is not enough. We need to know at which level the improvement happens — individual vote quality, or the aggregation process. This decomposition separates the two.

THE DECOMPOSITION
\(\bar{p}_{\text{vote}} = \dfrac{1}{n}\displaystyle\sum_i \dfrac{c_i}{K_i}\)    (per-vote correctness rate)
\(\Delta_{\text{per-vote}} = \bar{p}^{\text{guided}}_{\text{vote}} - \bar{p}^{\text{base}}_{\text{vote}} = 0.5894 - 0.5095 = +0.0799\)
\(\Delta_{\text{total}} = \hat{A}^G - \hat{A}^B = 0.6152 - 0.5288 = +0.0864\)
\(\Delta_{\text{aggregation}} = \Delta_{\text{total}} - \Delta_{\text{per-vote}} = 0.0864 - 0.0799 = +0.0065\)

T-2 · Paired Statistical Testing — Why McNemar, Not a t-Test?

📐
Why not a t-test? A t-test assumes independent samples. But here, the same question is answered under both conditions — the outcomes are correlated. McNemar's test uses only the discordant pairs (cases where conditions disagree), which is far more sensitive and statistically correct.
THE 2×2 CONTINGENCY TABLE
Guided Correct ✓ Guided Wrong ✗
Baseline Correct ✓ Both right (concordant) b = 2,528 ← McNemar uses this
Baseline Wrong ✗ c = 4,186 ← and this Both wrong (concordant)

Concordant pairs — where both methods agree — carry no information about which method is better. McNemar ignores them entirely.

THE FORMULA & RESULTS
\(\chi^2_{\text{CC}} = \dfrac{(|c - b| - 1)^2}{c + b} = \dfrac{(|4186 - 2528| - 1)^2}{4186 + 2528} = \dfrac{1657^2}{6714} = 408.94\)
\(p = 7.41 \times 10^{-92} \quad \text{(effectively zero)}\)
\(\widehat{\text{OR}}_{\text{matched}} = \dfrac{c}{b} = \dfrac{4186}{2528} = 1.656 \quad 95\%\ \text{CI: } [1.576,\ 1.740]\)

T-3 · Calibration Analysis — Does the Model Know When It's Right?

A model that is accurate but overconfident is dangerous in deployment — it claims to be sure when it isn't. Calibration metrics measure the alignment between a model's expressed confidence and its actual accuracy.

THREE CALIBRATION METRICS — DEFINITIONS
Brier Score
\(\frac{1}{n}\sum_i (p_i - y_i)^2\)
Mean squared error between confidence p and outcome y. Lower is better. Penalizes both wrong predictions and overconfidence.
ECE (Expected Calibration Error)
\(\sum_{m} \frac{|B_m|}{n}|\text{acc}(B_m) - \text{conf}(B_m)|\)
Groups predictions into 10 confidence bins; measures average |accuracy − confidence| gap. In this data, all bins are overconfident, so ECE = mean overconfidence.
NLL (Negative Log-Likelihood)
\(-\frac{1}{n}\sum_i [y_i \log p_i + (1-y_i)\log(1-p_i)]\)
The log-loss. Most sensitive to extreme overconfidence (p=1 when y=0 gives infinite penalty). Lower is better.
🔍 Key Insight: Why ECE = Overconfidence Gap Here

When every confidence bin satisfies confidence > accuracy (systematic overconfidence), the absolute values in ECE drop, and:

\(\text{ECE} = \sum_m \frac{|B_m|}{n}(\text{conf}_m - \text{acc}_m) = \bar{p} - \bar{y} = \text{Mean Overconfidence}\)

This reveals that the miscalibration is global and systematic (the model is always overconfident), not localized. Temperature scaling or isotonic regression could potentially correct it.

T-4 · AURC & Selective Prediction — Why Do We Need This?

In real deployments, a system can abstain on questions it's unsure about. AURC measures how well a model knows what it knows — its ability to rank its own predictions by reliability.

💡
Why AURC, not just accuracy? Imagine two models with the same accuracy. Model A's wrong answers are randomly scattered — you can't avoid them. Model B's wrong answers are concentrated in its low-confidence predictions — you can filter them out. AURC quantifies this difference. Lower AURC = you can avoid more errors by abstaining.

\(\text{AURC} = \int_0^1 \text{risk}(q)\, dq \quad \text{where } \text{risk}(q) = 1 - \text{acc}(q)\)
Sort predictions by confidence ↓. \(\text{acc}(q)\) = accuracy of the top-\(q\) fraction retained.

T-5 · Voting Theory — Why 5 Votes Don't Equal 5 Independent Samples

🎲
The fundamental problem: Majority voting's theoretical benefit assumes votes are independent. But five calls to the same LLM on the same question are highly correlated — if the model is wrong about something, it's likely wrong all five times. We quantify this dependence using the Intraclass Correlation Coefficient (ICC).
THE EXCHANGEABLE VOTE MODEL
Let \(X_{ij}\) = correctness of vote \(j\) for question \(i\), \(K_i\) votes, \(S_i = \sum_j X_{ij}\)
Under exchangeability with ICC \(\rho\):

Jensen's Inequality Correction — The Naïve Benchmark Overstates Reality
Naïve benchmark: \(A_{\text{ind}}(\bar{p}) = \sum_{j=3}^{5}\binom{5}{j}\bar{p}^j(1-\bar{p})^{5-j} = 0.6999\)
But \(A_{\text{ind}}\) is convex → Jensen: \(A_{\text{ind}}(\bar{p}) \geq \mathbb{E}[A_{\text{ind}}(p_i)]\)
Item-level corrected benchmark: \(\mathbb{E}[A_{\text{ind}}(p_i)] = 0.6135\)
Jensen gap: \(0.6135 - 0.6999 = -0.0864\) (naïve overstates by 8.64 pp)

The empirical majority accuracy (0.6356) falls between the corrected benchmark (0.6135) and the naïve upper bound (0.6999). Vote dependence — not sample size — is the binding constraint on ensemble benefit. Adding more votes helps little; diversifying votes helps a lot.

ICC by Architecture — Qwen Is More Correlated, Llama Is More Diverse
Higher ρ̂ means votes are more correlated → K_eff collapses. Higher p̄ means individual votes are more accurate.

T-7 · Falsifiable Predictions — How a Good Theory Makes Testable Claims

A scientific contribution isn't just about explaining past observations — it must make testable predictions about future experiments. The following five predictions follow directly from the theoretical framework and can be verified or falsified by the research community.

P1 · Vote Diversity

Reducing ρ̂ from 0.891 (Qwen) to 0.558 (Llama level) while holding p̄ = 0.696 constant should raise majority-vote accuracy from 0.696 to 0.709 (+1.31 pp).

→ Test: Apply diverse decoding seeds or varied system prompts to Qwen, measure ICC and accuracy delta.

P2 · Refiner Improvement

If the refiner (current: 28.88% accuracy on tie-break rows) achieves ≥55% accuracy, global guided accuracy should rise by ≥+1.0 pp. A refiner at 63.45% (majority-branch level) yields +1.93 pp.

→ Test: Replace coin-flip/refiner rows with a stronger verifier; measure counterfactual accuracy.

P3 · Operation Heterogeneity

On arithmetic benchmarks, guided Δ should fall in [+4, +20] pp. Sign-sensitive single-op tasks (subtraction, division) should be near the upper bound; multi-step near the lower.

→ Test: Any new arithmetic benchmark annotated by operation type.

P4 · Selective Prediction

At 62% coverage (high-confidence threshold), guided accuracy should exceed 74% while AURC stays below 0.304.

→ Test: Deploy with abstention policy at confidence ≥ 0.95; measure selective accuracy.

P5 · Bias-Substitution Fix

The PIQA-Llama-GSM8K pocket (Δ = −5.44 pp) should improve to ≥ −2.00 pp under condition-specific retuning of the tie-break policy, without degrading global accuracy below +8.0 pp.

→ Test: Audit solver option distribution before deploying; use content-grounded guide rather than structural.

T-8 · Mechanistic Conclusions

🎯
Planning, not voting, drives gains
7.99 pp of the 8.64 pp total gain (92.5%) comes from improved per-vote quality. Majority aggregation is secondary (+0.65 pp).
🔗
Vote dependence limits ensemble benefit
ρ̂ = 0.718 collapses K_eff to 1.29. Adding more votes helps little. Diversifying votes (lower ρ) is the correct intervention.
📊
Calibration & accuracy improve together
All four calibration metrics (Brier, ECE, NLL, MCE) and AURC improve significantly alongside accuracy. No accuracy–calibration tradeoff exists here.
⚙️
Tie-handling is the frontier
Fixing refiner + coin-flip rows yields +1.93 pp for free — the single highest-ROI optimization requiring no core architecture changes.
🌐
Broad generalization with one real exception
29/32 conditions show positive gains; 22/23 survive BH-FDR correction. Only PIQA-Llama-GSM8K (−5.44 pp) is a real deployment boundary.
📈
Confidence is a reliable signal
Confidence rises when correct (+0.055) and falls when wrong (−0.027). AURC −23.9%, top-decile accuracy +10.4 pp. High-confidence guided predictions are trustworthy.
