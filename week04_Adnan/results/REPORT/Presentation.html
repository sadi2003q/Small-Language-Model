① Compute Efficiency

What is Compute Efficiency?

The Question: Does the accuracy gain justify the extra cost?

We measure compute as parameter-passes — simply the number of model parameters multiplied by how many times the model runs. The guided pipeline costs 10.5B passes vs 7.5B for baseline — 40% more than baseline, but 30% less than just running the 3B model for all 5 votes (15B).

Simple Analogy

Imagine hiring a consultant (the guide) to write a brief strategy note before your team (5 workers) tackles a problem. The consultant costs extra time, but the team now works more efficiently with better direction. The question is: does the consultant's fee pay off in better results?

② Vote Consistency

02

What is Vote Consistency?

The Question: When the solver votes, how often do the votes agree — and are those agreements correct?

We run the solver 5 times per question. Vote consistency measures the fraction of those 5 votes that matched the correct answer. High consistency means the solver reliably reaches the right answer, not just getting lucky on a 3-2 split. A lift of 1.5× means guided consistency is 50% better than baseline.

Simple Analogy

Imagine asking 5 friends to solve the same puzzle independently. Without any guidance, maybe 2 get it right and 3 get it wrong (40% consistency). With a helpful hint, 4 out of 5 get it right (80% consistency). The majority vote then correctly picks the right answer — and more confidently.

③ Confidence Calibration

03

What is Confidence Calibration?

The Question: When the model is confident, is it actually correct? We use ECE (Expected Calibration Error) — lower ECE means confidence matches accuracy.

We treat vote agreement as confidence: if 5/5 votes agree, confidence = 100%. If 3/5 agree, confidence = 60%. A well-calibrated model at 100% confidence should be right ~100% of the time. ECE measures the gap between confidence and actual accuracy, weighted by how many questions fall in each bucket.

Real Example — PIQA Baseline Problem

On PIQA, the baseline solver votes A on 93.4% of questions — so 491 out of 500 questions have "100% confidence" (5/5 votes agree). But those unanimous answers are only correct 54.8% of the time — barely above random chance (50%). That is catastrophically miscalibrated: maximum confidence, minimum accuracy. ECE = 0.354. After guidance: ECE = 0.110, a 69% improvement.

Expected Calibration Error (ECE)
$$\text{ECE} = \sum_{b=1}^{B} \frac{|S_b|}{N} \cdot \left| \text{acc}(S_b) - \text{conf}(S_b) \right|$$

Where S_b = questions in confidence bucket b, acc = actual accuracy, conf = vote agreement. Lower ECE = better calibrated.

Statistical Proof

McNemar's Test — How We Prove It

Because every question is tested under BOTH conditions, we can ask: on the questions where the two conditions disagree, does guided win significantly more often than baseline?

?

Why McNemar's Test?

Standard tests assume independent samples. Here, each question is tested twice (guided and baseline) — they're paired. McNemar's test uses only the questions where the two conditions disagree. Questions where both got it right or both got it wrong don't count.

The 2×2 Contingency Table

(baseline correct)		 Baseline ✗
(baseline wrong)

Guided ✗ · Baseline ✓		 D — Both wrong

Only B and C matter for the test. A and D cancel out — they tell us nothing about which method is better.

McNemar Chi-Square Statistic (with Yates correction)
$$\chi^2 = \frac{(|B - C| - 1)^2}{B + C}$$

Under H₀ (no difference), this follows a chi-square distribution with 1 degree of freedom. Large χ² → small p-value → reject H₀.

Sample Size Planning

Power Analysis — How Many Questions Do We Need?

Power analysis tells us the minimum N required to have 80% chance of detecting a real effect, given the expected effect size. Too few questions → we might miss a real effect (Type II error).

N?

Simple Explanation

Imagine trying to determine if a coin is biased. If you flip it 5 times, you can't tell much. If you flip it 1000 times, you can be very sure. Power analysis calculates: given the effect size we expect, how many flips (questions) do we need before we can trust the result? The formula depends on the discordant rate (how often the two conditions disagree) and the signal strength (B-C difference).

Power Analysis Formula for McNemar's Test
$$N_{\min} = \left( \frac{z_{\alpha/2}\sqrt{\pi_d} + z_\beta\sqrt{\pi_d - \delta^2}}{\delta} \right)^2$$
π_d = π_B + π_C   (discordant rate = fraction of questions where conditions disagree)
δ = π_B - π_C    (signal = how much more often guided wins than baseline)
z_{α/2} = 1.96    (for α = 0.05, two-sided)
z_β = 0.842      (for 80% power)

The "Confident Misdirection" Failure Mode

On CommonsenseQA (N=250), the untuned 3B guide makes votes more decisive but more wrong. False-confidence cases increase from 54 to 65 — uncertain 3-2 wrong splits become unanimous 5-0 wrong answers. Fine-tuning's structured elimination format prevents this.

The Two-Layer Mechanism
What does model size contribute vs. what does fine-tuning contribute?
LAYER 1 — MODEL SIZE
Factual knowledge from pretraining that partially transfers when domain aligns with training content (science: +2 pts on ARC, math: +15 on SVAMP at high temp). Absent on commonsense — actively misleads.
LAYER 2 — FINE-TUNING STRUCTURE
Structured enumerated reasoning steps force content-based thinking, suppress positional heuristics, and create tight vote clusters. Adds +5–12 pts on top of Layer 1 across all domains. Always positive.
Special Finding

Position Bias Suppression

Small models often pick the same answer position regardless of content — the guide fixes this.

The PIQA Discovery
The unguided 1.5B solver picks Option A on 93.4% of PIQA questions — a binary choice task where 50/50 is expected. It's not reasoning about physical actions; it's defaulting to position A as a heuristic. The guide's verbal plan forces engagement with the question content, dropping A-selection to 42.1%. This single bias correction accounts for a substantial fraction of the +24.2 pt gain.

Boundary Condition

The RACE-High Null — When Guidance Doesn't Help

The N=500 clean null on RACE-High is not a failure — it tells us where and why the method works.

Reasoning vs. Retrieval
Verbal planning helps tasks that require generating a solution path. It does not help tasks that require locating pre-existing evidence in a passage. RACE-High answers are already in the text — the model just needs to find them. A plan can't help you search.
Simple Analogy

Reasoning task (PIQA, SVAMP): "How do you remove a stripped screw?" — You need to think through the physics and generate a solution. A verbal plan helps enormously.

Retrieval task (RACE-High): "According to paragraph 3, what year did X happen?" — The answer is already in the passage. Writing a plan first doesn't help you find the relevant sentence any faster.
